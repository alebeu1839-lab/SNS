# STEP2 練習ガイド — 第1位の候補を実際に自動化してみる

STEP1 が見つけた「車両情報を社内管理システムから掲載サイトへ転記」を、
練習用のモックシステムを相手に**実際に動かす**手順です。所要 15分。

自動化そのものより、**自動化を安全に回すための型**を体験するのが目的です。

---

## 0. 準備

```bash
cd worklens
pip install -r requirements-step2.txt
python -m playwright install chromium     # 初回のみ

# STEP1 のデモデータがまだ無い場合
python scripts/run_demo.py --reset --days 20
```

---

## 1. 練習用の2つのシステムを立てる

```bash
python scripts/run_mocks.py
```

| | URL | 実務での位置づけ |
|---|---|---|
| 社内管理システム | http://127.0.0.1:9101/cars | 転記元。**読み取りAPIあり** |
| 掲載サイト | http://127.0.0.1:9102/vehicles | 転記先。**APIなし・フォームのみ** |
| 問い合わせ受信箱 | http://127.0.0.1:9103/inbox | 第2位の候補で使う。**本文が自由文** |

この「取る側にはAPIがあり、入れる側には無い」が実務で最も多い組み合わせです。
だから**転記元はAPI・転記先だけRPA**にします。全部RPAにすると画面変更のたびに壊れます。

在庫12台のうち3台は、意図的に**そのままでは自動化できないデータ**にしてあります。

## 3. ドライラン（まず書き込まずに確認する）

```bash
python -m worklens.step2.cli run --candidate <上のID> \
  --map kanri.example.co.jp=http://127.0.0.1:9101 \
  --map keisai.example-portal.jp=http://127.0.0.1:9102
```

```
--- 自動処理できた 9件 ---
  48201  トヨタ アクア  2019年 42000km 1280000円
  ...
--- 人へ引き継ぎ 3件（自動処理していません） ---
  48204  価格が数値ではありません（応談）。掲載価格の判断が必要です
  48206  走行距離が未入力です。実車の確認が必要です
  48208  備考に確認事項があります（※要確認 修復歴の有無を確認中）

処理 12件 / 成功 9 / 引き継ぎ 3 / 失敗 0
```

**ここが一番大事な画面です。** 「12件中9件は自動でよい、3件は人が見る」という線引きを、
書き込む前に人が確認できます。この線引きが間違っていたら、判定条件
（`worklens/step2/recipes/web_transfer.py` の `validate`）を直してから先へ進みます。

`--map` は必須です。仕様に書かれた本番ドメインへ勝手に接続しないための安全装置で、
検証環境のURLを明示的に対応付けます。

## 4. 本番実行

```bash
python -m worklens.step2.cli run --candidate <ID> --mode live \
  --map kanri.example.co.jp=http://127.0.0.1:9101 \
  --map keisai.example-portal.jp=http://127.0.0.1:9102
```

ブラウザの動きを見たいときは `--headed` を付けます。

実行後、掲載サイトは9台になり、管理システムでは9台に「掲載済」が付きます。
**未掲載のまま残るのは、人へ引き継いだ 48204 / 48206 / 48208 の3台だけ**です。

もう一度実行しても二重登録になりません（完了印を見ているため）。

## STEP1 の仕様がどこで使われたか

| step2_spec の項目 | 使われ方 |
|---|---|
| `systems`（参照元 / 書き込み先） | `--map` でURLに解決され、どちらから取ってどちらへ入れるかを決めた |
| `open_questions`「APIがあるか」 | 調べた結果 → 転記元はAPI、転記先はフォーム。実装方針が決まった |
| `open_questions`「例外パターンは何か」 | `validate()` の判定条件になった（応談・未入力・要確認） |
| `guardrails` 3点 | ドライラン既定・全件ログ・想定外は人へ引き継ぎ、として実装した |
| `est_minutes_per_run` | 削減時間の実績計算に使った（成功件数 × 5.4分） |

## 自分の会社で同じことをするとき

変えるのは**1ファイルだけ**です。

`worklens/step2/recipes/web_transfer.py`

1. `fetch()` — 自社の管理システムからデータを取る方法に差し替える
   （API・CSV書き出し・DB直読み。無ければここもブラウザ操作）
2. `validate()` — 「どういうときは人が見るか」を書く。**担当者に必ず聞いてください。**
   ここを推測で書くと事故ります
3. `apply()` — 転記先フォームの項目名（`#vehicle_id` 等）を実際の画面に合わせる

基盤（`runner.py`）は業務を知らないので、触る必要はありません。
別の業務を自動化するときは、同じインタフェースで新しいレシピを足します。

---

## やってはいけないこと

- **ドライランを飛ばして本番実行しない。** 判定条件が正しい保証はまだありません
- **引き継ぎ件数がゼロになるまで判定を緩めない。** 引き継ぎは失敗ではなく、
  設計どおりの動作です。人の判断が要る仕事は人に残します
- **転記先に弾かれたのを成功扱いしない。** `apply()` は送信後の画面を必ず検証しています
- **最初から全件を流さない。** `--limit 3` で数件から始めて、結果を目で確かめます

## もう1つの業務も自動化してみる（第2位の候補）

「メールで受けた内容をExcelへ入力」は、転記とは実装の形が違います。

```bash
python -m worklens.step2.cli run --candidate <第2位のID> --mode live \
  --map "Outlook=http://127.0.0.1:9103" --map "Excel=./顧客管理.xlsx"
```

```
--- 自動処理できた 4件 ---
  m001  氏名=田中健一 / 希望車種=アクア / 予算(円)=1300000 ...
--- 人へ引き継ぎ 3件（自動処理していません） ---
  m004  希望車種を特定できませんでした
  m005  クレーム・至急の対応要請の可能性があります。担当者が読んでください
  m006  複数台の相談のため、台帳の1行に収まりません
```

`./顧客管理.xlsx` が実際に作られ、4行が入ります。

### 転記との違い

| | 第1位（転記） | 第2位（メール→台帳） |
|---|---|---|
| 入力の形 | 構造化されたデータ | **自由文** |
| 抽出 | そのまま使える | Claude（未設定時はルール） |
| 書き込み | ブラウザでフォーム入力 | Excelファイルへ1行追加 |
| 人へ回す条件 | 価格が数値でない等 | 車種・予算が読めない、クレーム、複数台 |

**LLMに欠けた項目を埋めさせません。** 本文に無いものは null のまま人へ回します。
「それらしく埋まった台帳」は、空欄より危険だからです。

### STEP1 と STEP2 の境界

STEP1（業務の発見）は**メール本文を一切読みません**。読む必要が無いからです。
STEP2 のこのレシピは、ユーザーが「自動化したい」と選んだ場合に限り、
業務として本文を扱います。人がやっていた作業の代行なので当然ですが、
**観測のために読むことと、業務として処理することは別物**です。
本文はレシピの中だけで扱い、収集データベースには保存しません。

## 対応していない業務を指定したら

```
「見積書をPDFで作成しメール送付」（書類作成・送付）に対応するレシピはまだありません。
  実装済みの業務種別: データ入力、データ転記
  この業務を自動化するには、worklens/step2/recipes/ にレシピを追加してください。
```

**別のレシピで代用しません。** それらしく動いて誤った業務を実行するほうが、
「できない」と言うより害が大きいためです。

---

## 人へ回った件はどこへ行くか

ダッシュボードの **/automation** に一覧で出ます。

- **引き継ぎは失敗ではありません。** 判断が要る仕事だけが人に残った状態です
- 同じ対象が毎回引き継がれても、未処理は1件に保たれます
- 対応が済んだら「処理済みにする」を押します
- **同じ理由が積み上がっていたら、そこが次の改善点**です
  （例:「予算が読めない」が多いなら、問い合わせフォームに予算欄を足すほうが早い）
